# Quality and qualification changes, 14 November 2026

This guide maps recent maintenance decisions to the code and repeatable checks. Read the
[architecture](ARCHITECTURE.md), [invariants](INVARIANTS.md) and [operations guide](OPERATIONS.md)
for the maintained contracts. Dated measurements do not replace those contracts.

## Ownership and recovery

Session loading reserves a key before constructing an entry. A concurrent child handoff cannot
install another mutable session, and a released lease cannot expose an entry later acquired by
someone else. Shutdown cancels provider and delivery I/O before joining workers, attempts every
cancellation stage and preserves the first failure with later failures suppressed. Storage stays
open while a worker may still use it.

Account work retains its bounded page and continuation cursor so continuously ready early accounts
do not starve later accounts. A failed read retries the same durable cut. Checkpoint preparation,
selected-source binding and member-address encoding have separate implementation owners; the
coordinator retains ordering and publication authority. See the [review map](INVARIANTS.md).

SDK operation helpers keep one deadline across submission and waits and pin the reviewed account,
document, operation and admission. An unrelated success cannot satisfy the wait. Ambiguous writes
are not retried automatically. Caller-owned JavaScript request payloads must remain immutable
while pending; the helpers do not deep-freeze every application object.

## Choose the qualification that answers the question

| Question | Entry point | Boundary |
| --- | --- | --- |
| Did the current published clauses carry a payment through Order to Agreement? | `scripts/qualify_clauses.py --orders 100` | Clause-only source, exact deployed package pins, signed application API, desired business state and exact root receipt, then independent whole-root replay. |
| Where does time go inside one clause operation? | Add `--profile` | Per-operation JFR adds overhead; keep these observations separate from unprofiled timings. |
| Does a retained isolated QA history match native execution? | `scripts/qualify_clauses.py --audit ACCOUNT ROOT` | Read-only replay; no new operations. Only `clause-qa-` accounts are accepted. |
| How does an owner update scale at 1/1,000/10,000 Orders? | `scripts/qualify_owners.py` | Native Contracts fixture with bulk initialization, not the published-clause journey or sequential creation of 10,000 Orders. |
| Does the complete deployed package catalogue fit its retained-memory budget? | `./gradlew catalogueRetentionProbe` | Local archive loading and mounts under a one GiB heap; no server, store or cloud work. |

Cloud commands are explicit opt-in tools. They verify the configured test account, record exact
artifacts and resource settings, create dedicated workers and request their termination even on
failure. A termination request is distinct from observing EC2's terminal state. The audit verifies
that state separately. Do not submit benchmark operations into an unrelated account.

The clause runner defaults to the current `Documents/Documents Clause` and uses a focused
catalogue whose aliases are checked against the deployed manifest. `--historical-clauses` explicitly
selects the retained older fixture. Counts are bounded to 1–100; above 20 the worker execution limit
is 45 minutes. Child discovery follows pagination. The larger campaign reproduced why absence
from the first 50 rows cannot establish that an embedded Order was not created.

Submission, visible business state and exact root-receipt completion have separate clocks. Child
page reads and polling contribute to the last two. HTTP client journeys add discovery, signing and
network cost. Whole-native replay proves agreement with this engine, not independent protocol
conformance. Retain failures and raw slow observations, and label every frozen runtime.

## Local gates and remaining limits

```bash
./gradlew check errorProne jacocoTestCoverageVerification
./gradlew jsonReadAllocationProbe catalogueRetentionProbe
python3 -m unittest discover -s scripts -p 'test_*.py'
```

At this revision the ordinary Java suite has 1,331 tests, the script suite 59, the SDK suite 71 and
the console suite 366. The CI workflow runs the clients separately and pins the sibling library.
It also retains the full-catalogue memory guard. Local checks do not imply that remote CI passed.

At 10,000 Orders the final native fixture still takes more time than at one Order: independent
child BlueIds do not make the Agreement's wide map identity or root metadata free to update.
Paced longevity runs also show latency drift and retain oracle evidence, so they do not isolate
engine retention or prove history-independent performance. No path or semantic-gas substitution
was used to hide this cost.

Caffeine informs lifetime, bounded retention and deterministic test design. A durable host also
needs transaction/retry discipline, operational recovery and independently reviewed protocols;
[readiness decisions](PRODUCTION-READINESS.md) keep those unfulfilled release requirements explicit.
