# Host trust boundaries

The HTTP console authenticates an account and resolves its session context. Immutable
content, a document ID, a BlueId and a signed provider statement are not interchangeable
with authorization. Account membership, reader access and business-channel admission must
each pass their existing checks. Native handlers and operator-selected packages are trusted
configuration; document-authored code does not become Java code.

Private rows and immutable pages remain account scoped. The shared public catalogue contains
only validated operator-installed package definitions. Its reserved storage scope is not a
valid tenant ID. Public byte availability never grants timeline access or permission to
perform an operation. See [the catalogue design](docs/PUBLIC-DEFINITIONS.md).

Durable heads publish only after referenced immutable content exists. Conditional claims
and versions reject superseded attempts. A failed input cannot justify dropping signed
history or guessing that a missing predecessor never existed. Preserve the distinction
between permission failure, incomplete evidence and a business rejection.

HTTP request logs contain generated request IDs, bounded route labels, method, response code
and dispatch duration. They omit credentials, payloads, query strings and arbitrary path
segments. Request IDs are generated by the server rather than trusted from caller headers.
Restricted operational diagnostics and JFR recordings still require controlled access.
`/live` checks the process; `/ready` checks worker health and a strongly consistent storage
read. Existing `/health` protocol information remains compatible. These endpoints are on
the private loopback API.

AWS secret custody, signed timeline validation, account isolation, bounded input handling,
timeouts and transaction tests are necessary controls, not an independent security review.
Do not expose the private API directly to the Internet. Keep backups of both private content
and public catalogue roots, and test the documented reader-compatible rollback boundary.
This test stack is a single instance and does not establish production availability.

Report suspected vulnerabilities privately to the repository owner with a small sanitized
reproducer, revision and observed authorization boundary. Do not place credentials or
customer document contents in public issues. No security certification or response-time
guarantee is claimed.
